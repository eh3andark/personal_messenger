# Chat Amn / چت امن

Maintained and published by **[eh3andark](https://github.com/eh3andark)**. Project repository: https://github.com/eh3andark/personal_messenger. Application code: [MIT](LICENSE) (© 2026 eh3andark); third-party fonts/icons have separate licenses in [NOTICE.md](NOTICE.md).

Chat Amn **4.2.0** is a Persian, RTL, responsive messenger for ordinary Apache/LiteSpeed cPanel hosting. **No database, daemon, CDN, remote font or third-party service is needed for core messaging.** The full Persian installation guide is **[README-FA.md](README-FA.md)**; [README.md](README.md) is the Persian GitHub landing page.

> This app is **not end-to-end encrypted** and is not an official Telegram client. The PHP server holds the decryption key. HTTPS and effective web-server access controls are mandatory for real deployment.

## Install

**From GitHub:** Prefer `hamrah-messenger-cpanel.zip` under **Releases → Assets**. GitHub's **Code → Download ZIP** and automatic **Source code (zip)** are source archives, not the deployment ZIP. If only source is available, extract it locally, run `python3 scripts/build_cpanel_zip.py` in its root (Windows Python Launcher: `py -3 scripts/build_cpanel_zip.py`), and upload the resulting ZIP from the *parent* directory. The builder uses Python's standard library only. Each new host generates its **own one-time setup token** on first opening `setup.php`; no token/password is shipped in GitHub. Full Persian instructions are in [README-FA.md](README-FA.md).

1. Verify PHP **7.4+** with `json`, `openssl`, `mbstring` and `fileinfo`; optionally enable `dom`/`curl` for public Telegram previews and web tools. Use an Apache/LiteSpeed-compatible server with working `.htaccess` and HTTPS. For Nginx, reproduce the access-denial rules yourself **before** deploying.
2. Extract **`hamrah-messenger-cpanel.zip`** into a separate directory such as `public_html/chat/`. Keep the shipped `.htaccess` and `data/.htaccess`; remove the uploaded ZIP from the public directory after extraction. Do not extract the fresh-install ZIP over a live site's `data/` directory.
3. Confirm `/core/bootstrap.php` and `/data/.htaccess` are denied (403/404). Open `/chat/setup.php`, read the randomly generated one-time setup token directly from `data/.setup_token.php` via your host's private File Manager, and choose your **own** administrator ID and password. No sample credentials are bundled.
4. Confirm `/data/users.json`, `/data/user_activity.json` and `/data/.master_secret.php` are denied too. Securely back up the **entire** `data/` directory and key together, off the web root. Losing the master key makes encrypted content unrecoverable. For upgrades, first back up code and data and test on a copy; replace application files, never overwrite `data/` with a clean package.

## Features and limits

- Auto-rotating JSON shards per conversation, atomic locked writes, server-side authenticated encryption of message bodies and completed media; private Saved Messages, folders and notes in a personal Drive. Storage capacity is bounded by your host and assigned quota, not unlimited.
- Admin-created accounts and permissions, unique exact-match IDs, user password/profile changes, safe reuse of an ID after deletion without inheriting its former owner's private data; incomplete legacy cleanup blocks reuse. Ordinary users cannot browse the global account directory.
- **Primary-admin-only account-usage dashboard:** exact account creation, last successful sign-in and last recorded online activity timestamps (Persian calendar, Tehran time); current online status, complete 24-hour days since last activity, never-signed-in/7-day/30-day filters and search. New accounts are recorded in private `data/user_activity.json`; presence comes from `data/presence.json`. Pre-upgrade creation dates cannot be recovered and are shown as unknown, not guessed. A background open tab can appear online without proving message activity. The report API rejects secondary admins and ordinary users; this metadata is not encrypted and must remain web-inaccessible and privately backed up.
- Private chats and groups/channels with membership access controls, private invite links, exact-ID **and public-name-only** discovery/join, member invitations and leaving; private rooms never appear in name search. A mandatory administrator-only announcement channel includes every existing/new account; the first setup admin is every user's permanent private-chat contact. Text, images, videos, voice, audio, arbitrary files, personal static stickers, reactions, replies, edits and search.
- A Telegram-like light default, dark and gentle pastel themes, interface animations respecting reduced-motion settings, and ten locally bundled, redistributable Persian/Arabic fonts (Vazirmatn, Estedad, Sahel, Shabnam, Samim, Parastoo, Gandom, Mikhak, Noto Sans Arabic, Noto Naskh Arabic). No runtime font CDN. Responsive RTL UI tested from desktop down to 320 px.
- Per-tab close signals make presence go offline after the last page closes (bounded 35-second fallback), without equating background tabs to closed tabs. Unread counts change only after an opened, visible chat is rendered and explicitly acknowledged. Channel posts display the channel title; group posts display individual senders. Per-account Enter-to-send, actual message font-size scaling, block/unblock enforcement, phone-camera attachment, consented location sharing, local Lucide icons and an installable PWA with a persistent top install control are included.
- At **80%** of the assigned quota, a prominent warning appears; **new media** is blocked while text continues to work. A first upload that crosses the threshold can finish. Cross-chat inventory of one's own uploads offers bulk deletion **only for me** or **for everyone** (the latter verifies the current password); remaining references, recipient downloads and backups are not erased.
- Explicit opt-in, browser-local large-video compression with original-upload fallback when compression/audio preservation fails. File uploads do not require an external transcoder.
- Optional assistant/search/Wikipedia tools under admin control; bounded Wikipedia extracts always link the full article, and length-limited web/AI responses disclose the limit. `/rates` reads public TGJU boards without an API key and labels source, rials/tomans, timestamp, stale/unavailable status; no hard-coded quotes or guaranteed live rate. Public Telegram preview reads up to **20 posts visible in the public HTML**, not private history; when direct CDN assets are present, bounded JPEG/video/audio/document import attempts save available files encrypted under the user's quota and report failures in the chat. Imports cannot promise originals, all media, large files, or 20 posts on every channel. Telegram login/Bot API is not required. `dom`/`curl` and outbound network access are needed for this optional feature.
- An admin-configurable **real GitHub repository URL** is hidden from the login page until saved; no fake link is shipped.

See the full Persian [GitHub publication & copyright guide](GITHUB-PUBLISH-FA.md), [CONTRIBUTING.md](CONTRIBUTING.md) for disposable-fixture test instructions and [SECURITY.md](SECURITY.md) for the full threat-model caveats. MIT permits copying, modification and commercial redistribution with notice preservation.

A typical local check uses `php -l` on all PHP files, `node --check assets/js/app.js`, `php tests/telegram_preview.php`, then the HTTP/Playwright suites against **a disposable fixture only**. `tests/account_activity.py` and `tests/browser_activity.cjs` exercise the new audit and primary-admin privacy on the disposable fixture. The suites intentionally reset test data. Do **not** run them against your live installation. Publishing to GitHub remains a separate, manual step described in [GITHUB-PUBLISH-FA.md](GITHUB-PUBLISH-FA.md); no commit, remote, or push is implied by receiving the source ZIP.
